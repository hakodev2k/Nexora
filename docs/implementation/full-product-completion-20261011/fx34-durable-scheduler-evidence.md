## Implemented behavior

SQL owns schedule progress. ProcessDueSchedule processes at most one due occurrence per wake-up. Serializable owner/definition/schedule locks atomically insert an occurrence, immutable-version-pinned Run/StepRun records, audit and next due time. Occurrence primary key (OwnerId,DefinitionId,ScheduleVersion,DueAt) prevents duplicate enqueue after restart. Existing queued runs coalesce to latest; Running/completed effects remain intact. Existing bounded Task worker/leases execute through Task service, never direct Task inserts.

Daily/Weekly, IANA/UTC, DST gap skip/fold first occurrence and MissedPolicy=Skip remain the bounded contract. Lateness strictly below 60 seconds may enqueue; lateness at or above 60 seconds records MissedOccurrenceSkipped and advances to a future occurrence without a catch-up storm. Unsupported cron/interval remains missing. No exactly-once external-effect claim.

Execution requires BOTH Automation:LocalTaskExecutionEnabled and Automation:LocalSchedulingEnabled (both default false), schedule Enabled opt-in and enabled Active definition. Authority is the owner's captured live session, saved with schedule or explicitly rebound when enabling the definition. Expired/revoked session/grant/module/source prevents enqueue. No permanent service authority is invented. Per-step scheduled dispatch and retry recheck originating schedule, version and current permissions; source edits, opt-out and operator switch stop queued future effects. Definition enable checks schedule binding and future occurrence before committing. Configuration editing remains allowed only on disabled definitions.

Migration 0052 adds default-off schedule opt-in and session snapshot, owner-scoped immutable occurrence outcomes, same-definition run FK, unique run association and recent-history index. No earlier migration checksum changed; no data reset or reseed. Migration application/replay NOT_RUN. Operator opt-out remains available in UI even while execution gate is inactive.
