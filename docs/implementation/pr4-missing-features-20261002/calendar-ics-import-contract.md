## Parsing and security limits

Technical local limits:1MiB ICS bytes,1000 VEVENT entries,100000 physical lines,64KiB unfolded content line, component depth8. Reject whole malformed envelope/encoding/structural nesting/limit breach before storing a batch. UTF8 strict decoding, optional BOM, CRLF export convention (parser also accepts LF); reject NUL and unsafe control bytes. Unfold at byte level before UTF8 decoding to handle a multibyte character split across folded lines. Required VCALENDAR VERSION:2.0 and PRODID. Unsupported VTODO/VJOURNAL/VTIMEZONE bodies are never executed or fetched. Registered runtime timezone IDs only; embedded VTIMEZONE cannot redefine them. Calendar methods never trigger sending/invites or network.

Each VEVENT keeps stable1-based source rowNumber. Required exactly one SUMMARY, DESCRIPTION, DTSTART, DTEND and UID. Decode TEXT escaped comma/semicolon/backslash/newline; reject invalid escaping, duplicated singleton properties, malformed parameters and oversized/blank fields. Title1..200, Description1..20000, UID1..1024 retain original case with ordinal comparison. UID is private content, excluded from errors/logs/audit. No invented business defaults; no DURATION-derived End. RRULE/RDATE/EXDATE/RECURRENCE-ID mark RecurringUnsupported. Missing/invalid fields have stable reason codes. VALARM is ignored, explicitly flagged in row warning; source STATUS is ignored and flagged when present. Unsupported properties/components are reported by fixed warning codes, not copied executable payload.

DATE uses YYYYMMDD; both endpoints must be date-only, no TZID; EndDateExclusive>StartDate. Store date columns authoritatively; use UTC midnight of those exact dates solely as deterministic legacy-sort compatibility values (not actual instants). DATE entries never resolve a local midnight, so midnight DST transitions/skipped civil days remain valid date intervals. Calendar range/view/form rendering uses authoritative dates, not conversion of this compatibility value; extreme date0001..9999 is permitted only with a representable strictly greater exclusive end. Account zone changes never alter either date. DATE-TIME uses strict YYYYMMDDTHHMMSS with optional Z, no numeric UTC offset in ICS. UTC endpoints preserve instant. TZID local endpoints resolve only registered TimeZoneInfo; floating endpoints use current saved User timezone, shown in preview. A local gap or ambiguity is skipped with explicit UnsafeLocalTime (no arbitrary DST branch choice); unknown TZID is UnknownTimeZone. End instant must exceed Start. Stored TimeZoneId is the account timezone; no remote TZURL resolution. Mixed time representation invalid. Required parsed row errors do not abort valid siblings.

No reminder/attendee/location/URL/attachment/Task/Project relation is created. Candidate DTO contains only schemaVersion,rowNumber,Title,Description, timed UTC pair OR all-day date pair, UID, account zone and fixed parser warning codes. No original raw file text is persisted in ImportRow. JSON is bounded and typed, not a generic update/history payload. Report renders literal text; no HTML or external navigation. Row errors expose only row number + allowlisted reason/warnings.

Overlap handling (P02-CAL-003/FX13-BR001): preview adds a nonblocking OverlapDetected warning against earlier valid candidates and currently readable owner Calendar records, without event titles/IDs/counts. Existing Manual rows are visible only under current calendar.event.read; Task rows additionally require current tasks.task.read and live source availability via the source-owned participant. If those reads are absent, report only fixed OverlapCheckUnavailable, never probe or disclose hidden records. The bounded cohort consists of at most10000 readable Event identities/revisions/time intervals (not contents); over-limit returns PreviewLimitExceeded without persisting a partial preview. Store a server-only digest of the exact visible cohort/visibility flags in batch options. Recompute before commit under the same Serializable transaction; any cohort/visibility change yields409 requiring a fresh preview, while newly duplicated UID handling remains deterministic after a new preview. The explicit Import Valid confirmation acknowledges overlap/omission warnings; no automatic rejection just because two intervals overlap. Date overlaps use date intervals in account zone, without changing authoritative DATE values or resolving unsafe midnight as actual business instants.
