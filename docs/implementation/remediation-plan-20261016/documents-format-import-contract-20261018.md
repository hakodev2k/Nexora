Unsupported comments, fields, OLE, images/media, pagination/layout and advanced tables are explicitly reported or rejected; no hidden fetch/execution. Clean embedded-image pinning remains an open integration and is reported omitted in modes without that capability.

DOCX converts paragraphs/headings/basic emphasis/lists/simple tables/code-as-text into Markdown, then, for explicit Block mode, the strict canonical text-block schema. Lossy cross-mode conversions report exact fixed warning codes: inline formatting flattened in plain Block text, headings beyond H3 normalized, nested structures flattened where schema cannot express them, omitted images/fields/comments, merged/table/layout changes. Unknown structured fields are never copied into commands. MD to Markdown preserves literal UTF8 text; raw HTML remains literal, unsafe URLs are not rendered/executed. MD to Block uses a bounded CommonMark AST with only approved GFM text extensions. Block IDs are deterministic per converted source/ordinal for repeatable previews, not business resource identities.

Read-only preview returns converted body, parser version, source digest, fixed warning codes and expiry5minutes; HMAC binds actor/owner/file/ETag/digest/mode/parser/converted digest/warnings/expiry. Token is not authority. No Preview job/record/page seeded. Unsupported format/schema and malformed ZIP/XML return sanitized fixed codes without source filenames, relationship targets or payload excerpts.

Manual Save POST supplies original source/mode/token, exact accepted warnings/confirmation and the full explicit new-page create intent (Title, Body, Type, Mode, optional Tag and immutable initial Folder OR Parent). Converted draft may be edited as ordinary owner content before Save; the command explicitly distinguishes edited body from original conversion and server validates final body independently. No trusted business/security field is derived from edited content. Changing mode requires a fresh conversion preview. New page uses Documents-owned CreateWithin participant and same owner document writer lock, never nested commit. Current file metadata/digest, composed actions, parent/Tag/body invariants, registry, one Page/version1, Operations committed import provenance, audits and opaque receipt are atomic. Distinct confirmed imports create distinct pages (duplicate titles are allowed); no implicit merge/dedup/overwrite invented. Same-key retry creates at most one page/job.

Receipt replay precedes fresh source state/ETag/token expiry, verifies original actor/owner/route/static+scope actions and returns original opaque page identity; it does not expose old source body/name or upgrade with a later read grant. Unknown result freezes original complete intent/key. No automatic source GET after ACK. Import provenance contains source/page identities, digest/parser/mode/outcome1 and timestamps, never cached filename/body/credentials. Source file lifecycle after commit does not delete/rewrite the created page. Original source file remains unchanged; no invented source retention/purge policy. Readable operation report is owner-scoped under current transfer.import.read/provider proof and projects no stale source metadata.
