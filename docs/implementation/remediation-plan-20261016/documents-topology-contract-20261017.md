## Bounded vertical implementation

DOC1 and DOC3 must be integrated before exposing child/folder page creation. Existing flat page CRUD alone cannot safely process a newly enabled tree. DOC4/5 compare/restore remain compatible and cannot change immutable location. DOC2 visual/editor and DOC6 sharing/format parity remain separate active work.

1. Add nullable FolderId/ParentPageId to Page, existing rows remain root pages outside folders. Add Folder with immutable parent, maximum two levels, Title1–200, duplicate titles permitted. Page trees also have at most two levels. A child inherits the parent's Folder; nonnull client Folder on a child is rejected. Root initially outside a Folder stays outside forever. There is no move/reparent endpoint or mutable field.
2. Enforce owner-composite FKs and depth constraints in SQL. Materialized FolderScope sentinel (zero UUID for none), checked against nullable FolderId, allows a child FK to bind the exact same folder scope as its root, including none. Depth/ParentDepth bind only to a level1 parent; no cycles or level3 can be created. Zero UUID is never a valid Folder/Page identity.
3. Register Page/Folder resource identities. Existing Page resource rows are a structural backfill from actual owner/type/lifecycle/timestamps, not mock business records or invented history. Abort migration on conflicting registry identity/type/owner; never overwrite a different resource. No historical archive/trash batches are synthesized. Old archived solo pages with known PreArchiveStatus can unarchive without inventing a former cohort; unknown legacy deletion provenance remains unavailable for restoration.
4. Listing is direct location: root outside folders, direct folder root pages, or direct children of a root page. Archived is a separate flat page list. Folder navigation is a separate DTO/query, stays navigation under page filters, never a fake Document row. Title/Tag search, Type/Tag/owner-local CreatedDate and updatedAt+SQL GUID ordering retain current semantics. Parent sidebar includes Archived child labels. Parent location uses current page.read; root library uses library.read, folder contents additionally folder.read.
5. Every Document/Folder/Tag writer acquires the same owner-scoped transaction applock (bounded5s) before graph/source locks. Parent lifecycle and child membership serialize with create/save/archive/trash/restore. Same SQL Serializable transaction owns source/action proofs, versions, cohorts, source registry, audit, receipt and sharing invalidation. External source participants use the caller transaction. SQL deadlock/timeout is a safe bounded error; no unbounded hidden retry.

## Cohort invariants and commands

Archive saves each currently nonTrash/nonArchived member's exact Draft/Published state in one ArchiveBatch/Member cohort. Independently Archived children keep their earlier cohort. Unarchive restores only current members of that cohort still Archived and nonTrash; skip missing/purged/Trash members. A child cannot unarchive while its parent is Archived. An explicitly restored formerly skipped child may subsequently unarchive under an active parent using its retained previous state. No lifecycle operation appends a content Save version.

Page/folder Trash freezes exact current nonTrash membership and parent/depth/state in operations.TrashBatch/Member, sets source DeletedAt/TrashBatchId and registry availability together, and invalidates affected page shares through Sharing's owned participant. Independently trashed descendants are excluded, never adopted into a new batch. Restore operates only on the frozen original root cohort, validates external original parents/folders active and not Archived, and never revives separately trashed/purged records. Source restoration does not reactivate revoked share links.

Preview for archive/tree-trash/restore/purge is read-only, CSRF protected if POST, with no fake mutation receipt. It returns root revision, opaque HMAC token over actor/owner/operation/root and sorted exact graph/member revisions and states. Protected child titles/IDs/counts are omitted when source read is denied; hidden effects use a fixed explanation. Command requires original root If-Match plus preview token and explicit confirmation; purge additionally requires literal `PURGE`. Token is not authority: current original composed actions and source/pins are rechecked. New descendants or revisions invalidate a preview. Source page/folder operations compose the corresponding child action when that member type is actually affected.

Existing transition clients may keep solo page publish/unpublish/archive/unarchive behavior; a transition expanding effects to descendants must require the explicit tree preview/confirmation. Generic request fields cannot silently create an aggregate effect the user did not confirm. New topology/cohort endpoints are wired only with their complete guards.

Purge is source-owned and limited to an exact Trash root/cohort. Refuse retained children/folders outside the cohort, active typed references, shared/file/version pins and unsupported dependency disposition. Never delete binary content or another source. Delete page versions only with page purge; remove owned archive metadata in dependency order, retain minimal Resource tombstones/Trash/audit metadata. Do not purge a parent while a separately trashed child still references it. No actual purge or migration is run by this agent.

## Replay, UI and security

Frozen mutation intent includes route, topology IDs, body, original versions/preview and UUID key. Receipt replay precedes fresh lifecycle/ETag/preview validation, verifies actor/owner/resource/original action/status, and returns only an authorized original projection or common opaque ACK. No title/body/hidden cohort data in receipt JSON, errors or audit. Final write/read/source checks follow audit and receipt. Lost read authority cannot return private detail; client clears projections and does not automatically GET after ACK. Unknown outcome freezes new commands until same-key retry or explicit discard/reconciliation.

UI adds breadcrumbs/back, Folder navigation, root/child creation with explicit type/mode each time, separate Archived/Trash locations, safe impact preview, cohort confirmation and conflict reload/reapply. Dirty/unload guards preserve draft/intent. Page cards/tables remain Title/Type/Tag only; no autosave, moves or inferred type/mode. Files/Sharing integrations use their owned participants, not new cross-module private-table shortcuts.
