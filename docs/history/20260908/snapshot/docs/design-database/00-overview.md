# Database overview and feature coverage

Review 2026-09-07 · Baseline `b85f0f314da8ca7dcee8dad156e7b538ba52c287` · Documentation only; no schema, migrations or application code executed.

## Authority and bounded design

Personal-only Public SaaS; each verified User has exactly one PersonalSpace. No Workspace, team, membership, collaborator, shared Vault or runtime custom-schema tables. User-selected SQL Server/.NET10/React/EF Core/Redis stack is preserved. SQL Server engine/edition/compatibility level remains deployment ADR, not inferred from .NET version. Tables below are a reviewed technical proposal, not permission to execute DDL.

## Ownership architecture

~~~mermaid
flowchart TB
    U["Identity and session"] --> P["PersonalSpace boundary"]
    P --> R["Resource identity registry"]
    M["Trusted module manifest"] --> T["Resource types and contracts"]
    T --> R
    R --> D["Typed domain aggregates"]
    D --> X["Atomic history and outbox"]
    X --> C["Search, reminders and projections"]
    C --> T
~~~

Registry is minimal identity/lifecycle, not EAV storage. A Project stays productivity.Project with relational Task children; a Page stays documents.Page plus immutable PageVersion. Cross-module relationships point to a registered resource and pass typed contract checks; these references never allow querying another module's DbContext.

## Not persisted as duplicate truth

Task Calendar entries, Project progress, Task Overdue, Goal ratios, TimeEntry duration, Dashboard summaries and Finance reports are read models. Cache/materialized indexes may be rebuilt; do not expose stale authorization or silently change financial totals. ManualEvent is separate because it has its own owner-entered lifecycle. Public Feed/Article/GitHub cache is physically distinct from private subscriptions/reading/saved state.

## Explicit gates

Finance semantics Q-05 and Vault recovery/key architecture Q-04 are conditional entire subdesigns. Shopee ingestion Q-06, automation/egress Q-07, production budgets/retention Q-08, account purge Q-01 and Interview Calendar Q-12 block affected workflows only. Their fields are documented to expose consequences, not to preempt PO choice. See [decision impact](../design-review/03-decision-impact.md).
